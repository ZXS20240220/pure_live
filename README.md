## 🔧 本分支改动说明（dev_20260910）

以下是相对于原始项目（upstream）在本分支所做的改动汇总。按功能维度分组呈现，**不暴露内部实现细节或接口路径**，仅描述改动意图与可感知效果。

### 零、上游同步（cherry-pick）

本分支在上述个人改动基础上，cherry-pick 了上游的部分更新并完成合并修复。以下变化直接来源于上游，非本分支独有：

- **新增 11 个平台适配器**：花椒、映客、AcFun、微博、小红书、Picarto、TwitCasting、Missevan、Inke、KilaKila、Openrec、TTingLive 共 11 个平台的 site adapter、弹幕解析、链接处理、分区 API 等完整实现
- **移除 Niconico**：上游因依赖限制移除了整个 Niconico 平台的实现
- **弹幕代码重构**：斗鱼、虎牙、Bilibili、抖音、SOOP、Twitch 的弹幕解析器均有不同程度的重构和改进
- **Huya Super Chat HTTP 请求修复**：绑定并关闭 HTTP 请求，避免连接泄漏
- **Douyin WebSocket 故障转移 + Cookie 脱敏**：WebSocket 连接失败时自动切到备用方案，Cookie 在日志中脱敏处理
- **CC 分类 API endpoint 修复**：修正 CC 直播分类接口地址
- **搜索页重构**：搜索页面 UI 和交互做了较大调整
- **live_site 接口小幅调整**、**danmaku_controller 重构**、**multiview_danmaku_session 增强**

以下第一至二十七节描述的是本分支独有的改动，与上游 cherry-pick 无关。

---

### 一、移除 Firebase 用户同步模块

原始项目包含一套完整的 Firebase 邮箱/匿名登录系统，本分支出于**简化依赖、降低构建复杂度和隐私考量**，完整移除了 Firebase 相关功能：

- 删除用户认证模块及全部关联配置文件
- 清理移动端（Android / iOS）Firebase 集成配置
- 清理桌面端（Windows / macOS）插件注册
- 清理 Gradle 与 Dart 依赖
- 精简备份页面：移除 Firebase 云端备份入口，保留 WebDAV 和本地备份

### 二、主播信息扩展

直播间数据新增五类主播信息字段，用于在 UI 上展示更丰富的主播画像：

- **主播等级**：如斗鱼 / 虎牙的段位等级，Bilibili 的主播等级
- **公会名称**：主播所属公会（斗鱼直接返回，虎牙需额外请求）
- **开播时间**：当前直播 session 开始的时间戳；抖音离线房间保留上次开播时间
- **订阅数**：主播总粉丝数，斗鱼从主播卡片接口获取，Bilibili 从房间信息中提取，抖音从关注信息字段解析
- **IP 属地**：主播所在地城市（当前仅抖音返回）

字段已集成到现有的数据序列化与同步链路中，保持前后兼容。刷新不获取的字段（如订阅数、AI 看点、开播时间等）会从旧数据中回退保留，不会被刷新响应覆盖清空。

### 三、各平台数据增强

在原有平台适配基础上，补充解析并展示更多主播和弹幕相关信息。

#### 斗鱼直播

- **AI 看点完整历史列表**：调用斗鱼官方 AI 看点接口获取完整看点历史（此前只取第一条摘要），每条看点包含标题、时间戳和描述，按时间正序展示
- 解析主播等级、公会名称、开播时间、**主播订阅数**
- **上次直播时间**：未开播或回放房间显示主播上次开播的时间
- **弹幕等级 + 粉丝牌**：每条弹幕解析发送者的用户等级、粉丝牌名称和等级，在弹幕列表中以徽章形式展示
- 标题与介绍文本做 HTML 标签清除与实体解码，避免乱码或标签外露
- 分类区域显示子分类名称（如"英雄联盟 / 云顶之弈"）
- 修复某房间数据字段为空时可能导致的崩溃
- Super Chat 解析保留 price=0 预览包去重逻辑（暂未启用，待确认）

#### 虎牙直播

- 解析主播等级、开播时间、**公会名称**
- **上次直播时间**：未开播或回放房间显示主播上次开播的时间
- **弹幕等级 + 粉丝牌**：从 Tars 协议的装饰字段中解析用户等级和粉丝牌（appId 10400），弹幕列表中以徽章形式展示
- 介绍字段预留给 AI 看点等特殊用途

#### Bilibili

- 解析开播时间、**主播等级和订阅数**（从房间 anchor_info 中提取）
- **弹幕等级 + 粉丝勋章**：从弹幕 richer 字段解析用户财富等级和粉丝勋章；旧版协议从 info[3] 数组提取，做了双路兼容
- 介绍文本做 HTML 清洗

#### 抖音

- **开播时间 + 主播地理位置**：从 reflow 接口解析开播时间和主播所在地城市（如"上海"），未开播房间保留上次开播时间
- **订阅数**：从关注信息字段解析总粉丝数
- **弹幕等级 + 粉丝团徽章**：从 badgeImageList 解析用户等级（imageType 1）和粉丝团（imageType 7）

#### CC 直播 / 快手 / SOOP / Twitch 等

- 介绍字段做统一清空处理，避免与平台简介重复显示

### 四、HTML 文本净化工具

新增一套 HTML 处理工具，用于从各平台返回的原始文本中清除 HTML 标签、解码 HTML 实体，得到纯文本展示内容。

### 五、直播头部功能增强

直播间顶部主播信息区新增多项 UI 和交互能力：

- **主播等级徽章**：橙色小徽章显示在昵称左侧
- **公会名称标签**：蓝灰色小徽章显示在昵称右侧
- **IP 属地**：主播所在地城市（如"上海"）显示在昵称右侧（当前仅抖音返回）
- **订阅数内联显示**：关注/已关注按钮中内嵌主播订阅数（格式如 `1.2万 | 已关注`），悬停显示完整数字 tooltip
- **直播时长计时器**：红色圆点 + 时分秒格式，每秒刷新。仅对返回开播时间的平台（斗鱼、虎牙、Bilibili、抖音）显示
- **介绍悬浮提示**：鼠标悬停时弹出完整主播介绍
- **快速操作按钮组**（5 个）：
  - 🏷️ 设置房间标签
  - 🌐 打开原平台直播间
  - 🔄 切换到其他关注的直播间
  - 🔗 获取直播直链
  - 🪟 新窗口独立打开（仅 Windows）

### 六、键盘快捷键重构 + 焦点守卫

原先的快捷键实现依赖嵌套焦点树中的回调绑定，在复杂布局下容易被其他组件抢走键盘焦点，导致按键失效。改为全局监听原始硬件按键事件后，所有快捷键均可稳定触发。

**同时新增焦点守卫机制**：文本输入框获得焦点时，除 `Esc` 外所有快捷键自动禁用，避免打字时误触发播放暂停、翻页等操作。`Esc` 键始终放行，保证输入框内可以正常退格、关闭弹窗。

该守卫同时应用到了收藏页面的翻页控件，左右翻页箭头在输入框获得焦点时也不会误触发。

#### 直播播放页快捷键

| 按键                            | 功能                                                  |
| ------------------------------- | ----------------------------------------------------- |
| `Space` / 播放键              | 播放 / 暂停                                           |
| `↑` / `↓`                 | 音量增减 5                                            |
| `←` / `→`                 | 直播时移，向前 5s / 向后 5s（仅缓存已覆盖区间内有效） |
| `Shift + ←` / `Shift + →` | 大步长时移，向前 / 向后 30s                           |
| `E`                           | 跳回直播边缘（回到实时直播位置）                      |
| `R`                           | 刷新直播                                              |

| `Esc`                         | 退出全屏 / 退出窗口全屏 / 返回（原有逻辑，始终放行）  |

> 文本输入框获得焦点时，除 `Esc` 外所有快捷键自动禁用（焦点守卫）。

| `↑` / `↓`  | 整页滚动（向上 / 向下翻一屏）  |

### 七、房间标签设置对话框：自动选中已有标签

打开「设置房间标签/分类」对话框时，原先所有复选框都是空的——因为它直接读取房间对象上的 tagIds 字段，而该字段在很多场景下为空或是旧数据。修复后改为从标签管理控制器的"房间→标签映射表"中查询该房间真实已绑定的标签，已勾选的会自动显示 ✅ 状态，避免每次都要重新勾选一遍。

> 直播头部快速操作按钮组里的 🏷️「设置房间标签」按钮正是调用这个对话框。

### 八、置顶排序逻辑重写 + 置顶开关 + 卡片徽章

#### 显式置顶机制

原先通过"标签名字匹配关键词"（如 ❤️、置顶、特别关注、pin、vip）来识别置顶标签，这种方式不直观也不灵活。改为**显式置顶**：置顶标签永远是标签列表的**第一个**标签，由用户通过标签管理页面手动点击置顶图标设定。

#### 排序逻辑

在线房间：置顶房间优先 → 再按选定的排序策略排列（默认按热度，可切换为按开播时间或按观看时长）。回放房间仅按排序策略排列，不混入置顶逻辑。

#### 置顶显示开关

收藏页面顶部工具栏新增置顶开关按钮。关闭后置顶标签仍保留但不影响排序，收藏列表退化为纯按选定策略排列。

#### 房间卡片置顶徽章

每个房间卡片右上角新增置顶小徽章（📌），表示该房间带有置顶标签。开关关闭时徽章不显示。

### 九、收藏页面排序策略切换 + 升降序

收藏列表顶部新增排序策略菜单，支持三种在线房间排序模式：

- **按热度**（默认）：原始行为，按观看人数/热度降序
- **按开播时间**：按主播开播时间升序，方便快速找到刚开播的直播间
- **按观看时长**：按累计观看时长排序，帮助识别自己最常看的直播间

回放房间在"按热度"和"按开播时间"模式下按观看人数排序。

#### 观看时长排序的特殊性

与前两种模式不同，**按观看时长**对所有状态的直播间（在线 / 录播 / 离线）统一生效。在"全部"Tab 下，三种状态的房间合并后按观看时长统一排序，而非按状态分桶拼接；在其他 Tab 下，各自也用同一规则排序。因此排序按钮在任何筛选条件下都可用。

#### 升序 / 降序切换

排序按钮旁新增**升序 / 降序切换按钮**，对三种排序模式统一生效：

- 降序（默认）：热度最高 / 开播最新 / 观看时长最多在前
- 升序：热度最低 / 开播最早 / 观看时长最少在前

置顶房间和标签匹配分始终优先于选定的排序策略，不受升降序影响。升降序偏好持久化保存，重启后自动恢复。

### 十、收藏页面 Tab 扩展 + 计数徽章

收藏页面原先三个状态 Tab（在线 / 录播 / 离线）扩展为**四个**：新增"全部"Tab，显示所有关注房间的并集。默认选中"在线"Tab。

所有 Tab 和平台 Tab 均带**计数徽章**：

- 状态 Tab：`全部 (N)`、`在线 (N)`、`录播 (N)`、`离线 (N)`，数字实时反映各状态的房间数量
- 平台 Tab：`平台名 (N)`，数字显示该平台在当前选中状态下的房间数

切换状态 Tab 时计数自动更新；平台 Tab 的计数同时受状态筛选条件影响。排序按钮仅在"全部"和"在线"Tab 显示。

### 十一、"伪"开播时间计算（已弃用）

部分平台（如抖音）的 API 不返回真实开播时间，原先尝试用"在线状态变化的当前时刻"近似计算一个伪开播时间供排序和 Header 显示使用。后因无法可靠区分"真实的 offline→online"和"API 抖动/网络闪断造成的假状态切换"——后者会把伪时间写成接口恢复的时刻，偏差可能好几个小时；且 App 重启后持续在线的房间又永远拿不到伪时间——整套方案精度不可控，暂时整体停用。日后如有更可靠的时机确认方式可移除注释重新启用。

### 十二、收藏页面搜索功能

关注页面顶部新增搜索框，支持**多关键字空格分隔**的模糊搜索（OR 逻辑，任一关键字匹配即命中），搜索范围覆盖：

- 直播间标题
- 主播昵称
- 房间号
- 该房间绑定的所有标签名称

输入停止 200ms 后自动触发搜索，无需手动点击。搜索框获得焦点时，收藏页面的左右翻页快捷键自动禁用（焦点守卫）。

### 十三、关注页面标签多选筛选 + "无标签"虚拟标签

#### 标签多选筛选（并集模式）

标签栏新增多选模式开关。开启后可同时选中多个标签，筛选逻辑为**并集**——只显示同时拥有所有选中标签的房间。关闭多选模式则恢复为默认单选切换。

#### "无标签"虚拟标签

标签栏新增一个固定的"无标签"虚拟标签（带计数徽章），点击后筛选出所有**未绑定任何标签**的直播间。该虚拟标签与多选模式可联动——例如同时选中"无标签"和某个真实标签，筛选"无标签 **或** 该标签"的并集结果。

> 为避免语义冲突，用户现在**不能再创建名为"无标签"、"全部"、"all"、"untagged"的自定义标签**，标签管理控制器会在创建/编辑时自动拦截。

### 十四、标签管理增强

#### 标签卡片显示房间数量

标签管理页面的每个标签卡片右上角新增数字徽章，显示当前**有多少直播间绑定了该标签**，超过 99 显示为 `99+`。

#### 一键匹配分类标签

主菜单新增「一键匹配分类标签」入口。点击后弹出确认提示，确认后自动扫描关注列表中的所有直播间，读取每个房间的平台分区信息（如"英雄联盟"、"DOTA2"、"颜值"等），并：

1. 自动创建缺失的分类标签
2. 将房间绑定到对应分类标签
3. 跳过已绑定的房间
4. 跳过没有分区信息的房间

执行过程中显示实时进度条，完成后弹出统计摘要（扫描总数、成功匹配数、新建标签数、跳过数、无分区数）。

### 十五、幽灵标签问题修复

在使用过程中发现一个"幽灵标签"问题：用户删除了某个自定义标签后，房间→标签映射表中仍保留着已删除标签的 ID。这会导致：

- 房间实际已无标签，但映射表还认为有（旧 ID）
- `getTagsForRoom()` 返回无效 ID，其他功能因此出错

**修复方案**：

- 应用启动时自动扫描并清理映射表中已不存在的标签 ID
- `getTagsForRoom()` 返回时再次过滤，只返回有效的标签 ID
- 删除标签时，同步遍历所有房间的标签引用并移除，必要时清理空引用的房间条目

### 十六、收藏列表刷新：并发策略 + 保护与取消 + 冷却

收藏刷新的并发模型从单一全局并发池重写为**按平台分组、每个平台独立限流器**：

- 默认全局并发上限从 4 降为 2（单平台主机约 2-3 并发即可，避免触发风控排队或验证）
- **每个平台独立并发**：不同平台的刷新请求各自进入独立的有界并发池，混合关注列表时真正跨平台并行；单平台列表保持在该平台的突发上限内
- **按平台独立配置**：设置页面新增每个平台的独立并发设置（默认跟随全局，推荐值 3 路），可单独覆盖
- **跳过隐藏平台**：被用户设置隐藏的平台不进入刷新队列，既省流量又降低风控暴露

同时保留已有的刷新保护机制：

- **刷新保护**：防止短时间内重复触发全量刷新
- **手动取消**：刷新进行中工具栏出现取消按钮，点击后中止本次刷新并保留已获取的数据
- **成功冷却**：单个房间刷新成功后有 30 秒冷却期，冷却内不再重复请求；失败的房间有 5 分钟冷却，两者独立计数
- **合并策略优化**：刷新返回的数据与本地缓存做智能合并——新值覆盖旧值，但刷新不获取的字段（订阅数、公会、AI 看点、开播时间等）从旧数据回退保留，避免刷新把非核心字段清空
- **刷新遮罩语义区分**：启动时显示"正在核验全部关注与历史直播间…"，手动全量刷新显示"正在刷新全部关注直播间…"，按当前筛选条件刷新（平台/标签/搜索）时显示"正在刷新当前筛选的关注直播间…"，三种场景语义清晰可辨

### 十七、开播状态/平台切换时重置筛选

用户在关注页面切换了直播状态筛选（在线/离线/全部）或平台筛选后，标签筛选和搜索条件的联动重置逻辑做了优化，避免出现"筛选条件和内容不匹配"的视觉错位。

### 十八、切换直播间面板

原先的"切换直播间"功能是一个全屏对话框，无法嵌入其他布局。重构后抽取出可复用的面板组件，并持续扩展功能。

#### 两种形态

- **侧栏组件**（持久化模式）：嵌入弹幕侧栏作为 Tab，切换直播间时**保持状态**——包括选中的页签、筛选条件等，只有从直播间返回上一级（Esc / 左上角返回）时才重置
- **悬浮窗口**（临时模式）：通过直播头部右上角按钮呼出，拖动标题栏可自由移动；关闭后**立即重置为默认状态**

#### 页签精简

原先的三个页签（已开播 / 观看记录 / 录播）精简为**已开播 + 观看记录**两个，录播页签移除。

#### 平台 / 标签筛选下拉框

页签右侧（右对齐）新增两个单选下拉筛选框：

- **直播平台筛选**：只列出当前已开播房间实际涉及的平台（如只有斗鱼和虎牙有开播，就只显示这两项）
- **标签筛选**：只列出当前已开播房间涉及的标签

两个筛选框默认都是"全部"，选中某一项立即生效。已开播和观看记录两个页签**同时受这两个筛选条件影响**，顶部刷新和清空历史按钮不受筛选约束。

#### 排序复用收藏页

已开播列表的排序逻辑直接复用收藏页面的排序策略和置顶开关：

- 排序模式（按热度 / 按开播时间 / 按观看时长）
- 置顶房间优先 + 置顶开关控制
- 卡片左上角显示置顶徽章（📌），同样受收藏页置顶开关影响

#### 下拉刷新

已开播和观看记录两个页签均支持下拉刷新（参照主菜单历史记录页面的交互）：

- 已开播下拉刷新 = 点击顶部刷新按钮（功能一致）
- 观看记录下拉刷新 = 单独刷新历史记录

#### 其他已有的能力

- 历史 Tab 顶部 🗑️ 清空历史按钮
- **历史记录单个删除**：长按/右键某条历史可单独移除
- 实时监听收藏变更、房间切换、历史变动等事件，自动刷新
- 历史房间同步收藏夹的实时直播状态，过滤离线房间
- 多画面选台面板复用该逻辑

### 十九、Super Chat 面板增强

#### AI 看点完整历史列表

当斗鱼直播间返回 AI 看点数据时，Super Chat 面板顶部展示**全部历史看点**（按时间正序排列），不再只展示第一条摘要。每条看点独立展示标题、时间和描述。没有 AI 看点数据时该区域自动隐藏。

#### 醒目留言手动刷新 + 下拉刷新

Super Chat 面板顶部保留 🔄 刷新按钮，同时整个面板支持**下拉刷新**——下拉到顶松开即可重新拉取当前直播间的醒目留言和 AI 看点数据，不必手动重新进入直播间。

### 二十、直播时移回放（基于播放器缓存）

#### 可拖动时移

基于底层播放器（MPV / MediaKit）的缓冲窗口，新增直播时移能力：

- 播放器实时解析 MPV 的 `demuxer-cache-state` 日志，得到当前已缓冲的 seekable 区间列表
- 进度条扩展为可拖动模式，在已缓冲区间内自由定位
- 拖出缓冲区间时，自动触发底层流重连 seek 回到直播边缘

#### 快捷键

| 按键                            | 功能                               |
| ------------------------------- | ---------------------------------- |
| `←`                          | 向前时移 5s（仅缓存已覆盖区间内） |
| `→`                          | 向后时移 5s（仅缓存已覆盖区间内）  |
| `Shift + ←` / `Shift + →` | 大步长时移 30s                     |
| `E`                           | 跳回直播边缘（恢复实时播放）       |

#### 回到直播

进度条右侧始终显示"回到直播"按钮，点击或拖动到最右端可立即跳回实时直播边缘。`E` 键等价于点击这个按钮。

#### 进度条时间显示

进度条左侧新增**缓存窗口时长标签**，显示当前可回看的时间范围（例如 `5:00` 表示可回看最近 5 分钟）。标签值随缓存窗口滑动自动更新——当旧内容被驱逐、新内容被缓冲时，标签会实时反映实际可回看的时长。在刚进入房间、seekable ranges 尚未计算出来之前，标签暂时显示当前已缓冲的时长。

### 二十一、侧边栏宽度可拖拽调整

播放页右侧弹幕侧栏（或多画面布局中的侧栏）新增可拖拽的分隔条：

- 鼠标悬停到侧栏左边缘时自动显示可拖拽区域
- 按住左键左右拖动即可调整侧栏宽度
- 调整后的宽度会**记忆化保存**，下次进入直播间自动恢复

### 二十二、沉浸式侧边栏体验（Windows 桌面端）

桌面直播播放页的侧栏做了沉浸式重构，提供更纯粹的观看体验：

#### 面板透明度调节

侧栏背景不再是完全不透明，而是支持**透明度调节**（范围 20%–100%，默认 92%）。调节方式：

- 鼠标移动到侧栏左边缘的控件区，出现**垂直滑块**（横向放置），直接拖动调节
- 在滑块上滚动鼠标滚轮，每次增减 5%
- 调节值实时保存记忆

#### 面板自动隐藏与展开

- 面板关闭状态下，屏幕右侧 80px 区域为**感应区**，鼠标进入 300ms 后自动展开面板
- 面板打开状态下，鼠标移出面板区域后自动收起（3 秒延迟，给用户留出操作缓冲）
- 面板锁定状态下不自动隐藏

#### 面板锁定

侧栏边缘控件区提供**锁定/解锁按钮**。锁定后面板保持当前状态，不响应鼠标悬停自动展开/收起。

#### 桌面端沉浸式全屏

在播放设置中启用沉浸式布局模式后：

- 进入直播播放页时**隐藏窗口标题栏**，实现真正的全屏观感
- 侧栏面板同样使用透明度叠加在视频画面之上
- 标题栏自动恢复条件：切换到非沉浸式布局、窗口最小化、退出全屏等

#### 边缘控件区

面板打开时，左侧 36px 宽的边缘区域在鼠标悬停时显示操作控件：

- 🔒 锁定/解锁按钮
- 透明度数值显示（如 `92`）
- 垂直透明度滑块（可拖动 + 滚轮调节）

### 二十三、弹幕列表增强

弹幕列表在原有功能基础上做了多项交互改进：

#### 清屏按钮

鼠标移动到弹幕列表区域时，右上角显示**清屏按钮**（🗑️）。点击后弹出确认对话框，确认后立即清空当前弹幕列表，释放内存占用。

#### 滚动策略优化

- **滚动到底部自动恢复**：用户手动上滑暂停自动跟随弹幕（显示"新消息"提示），当滚动条滑回直播边缘（最新消息位置）时，自动恢复自动跟随，无需手动点击"回到底部"按钮
- **简化滚动判定**：去掉了对指针活动状态的额外守卫，桌面端鼠标滚轮滚动也能正确触发"暂停自动跟随"逻辑
- **鼠标进入检测**：新增鼠标进入列表区域的检测，用于显示清屏按钮等悬停元素

#### 弹幕粉丝牌显示修复

修复了粉丝牌显示的一个隐藏 bug：原先只有粉丝牌**名称**非空时才显示徽章，但实际上佩戴粉丝牌是用户可选的——有些用户可能选择不显示名称但等级仍然存在。现在只要有粉丝牌等级就显示徽章，名称为空时只显示等级数字。

### 二十四、音量控制优化

- **鼠标滚轮方向转换**：新增滚轮方向转换器，当音量滑块处于水平布局时，垂直滚轮会正确映射为水平音量调节方向
- **左键拖动调节**：拖动音量控件时的交互做了平滑处理

### 二十五、播放器接口统一 + 启动/构建优化

#### 播放器接口统一层

新增播放器统一接口层，屏蔽底层不同播放器（MPV、MediaKit、VideoPlayer、FIJK）的实现差异，向上层播放页提供一致的 API。时移缓存逻辑、音量控制、返回处理等能力统一挂载到这一层。

#### 启动速度优化（Release 构建）

- **BoundedAsyncPool**：并发限制的异步任务池，替换原先无约束的并发启动逻辑，减少应用首屏的主线程抢占
- **路径管理预初始化**：应用路径管理器提前准备好所有本地存储路径，避免启动阶段的多次磁盘 IO
- **清理冗余等待点**：部分可并行的启动步骤从串行改为并行

#### 按钮样式微调

直播菜单按钮、标签选择器等组件的视觉样式做了细节调整（间距、圆角、图标尺寸等），使整体更协调。

### 二十六、多画面返回崩溃修复

多画面播放模式下，原来的返回逻辑在某些显示模式切换时会触发空指针异常。修复方案：

- 统一所有返回操作走同一个处理函数，覆盖全屏/窗口全屏/小窗等多种退出路径
- normal 模式下也加了显式的返回按钮
- 多画面选台面板的历史来源同步收藏夹的实时直播状态，并过滤已离线的房间

### 二十七、历史记录刷新策略统一

#### 统一刷新接口

历史控制器抽取出独立的 `refreshRoomDetails` 方法，所有需要刷新历史房间详情的场景（主菜单历史页面下拉刷新、切换直播间面板观看历史下拉刷新、启动校验历史补全）统一复用这套接口。之前 history_page 和 play_other 各自重复实现了一套刷新逻辑，现在彻底消除代码重复。

#### 对齐关注刷新的并发策略

历史刷新的并发模型与收藏刷新完全一致：

- 按平台分组，每个平台独立限流器，复用平台级并发上限配置
- 平台提供轻量 `getRoomDetailForRefresh` 接口时优先使用，否则回退完整 `getRoomDetail`
- 单房间 12 秒超时，失败保留旧数据，不产生假离线状态
- 返回结果与输入同序，身份对齐（平台更换 canonical id 也不会错位）

#### 启动校验延伸到历史记录

应用启动时，收藏列表核验完成后自动触发一次历史记录的轻量校验：

- 历史中与收藏身份一致且收藏校验成功的房间**直接复用收藏结果**，不重复发请求
- 不在收藏中、或收藏校验标记为 unknown 的历史房间走独立的历史轻量刷新
- 写回前重读当前历史列表，刷新期间新增/删除的条目不受影响

#### 历史变更事件总线

历史控制器在增删房间、清空历史时会发出统一的"历史已变更"事件信号，供切换直播间面板等组件监听。解决了"删除历史后面板没及时刷新"的问题。

### 二十八、观看时长记录

#### 计时规则

应用自动为关注列表中的直播间累计记录观看时长，核心规则：

- **只记录关注的直播间**；取消关注后，该直播间的累计时长自动清空
- **只记录已开播状态**的直播间（录播不计时）
- **直播流开始播放**后才开始计时；暂停、手动停止播放、或直播流连接失败时停止计时
- 直播半途网络断开自动停止，恢复后继续累加
- 直播间内拖动进度条进行时移回放**仍然计时**
- 记录的是**累计时长**，单次会话不单独记录

#### 持久化

观看时长数据持久化存储在本地，退出程序不清空，下次打开自动恢复。

#### UI 展示

- **直播头部**：观看时长显示在"已播时长"（直播 session 时长）**上方**，两行堆叠对齐。鼠标悬停显示完整累计时长 tooltip
- **房间卡片封面左下角**：显示累计观看时长徽标（如 `12h 30m`），无记录时不占位

#### 排序集成

"按观看时长"排序模式直接读取累计时长，见第九节。用户在直播中，时长会被实时累加并防抖刷新排序位置。

#### 管理

- **主菜单清空**：主菜单新增「清空所有观看记录」入口，点击后弹出确认对话框，确认后清除全部观看时长数据
- **旧数据兼容**：取消关注时自动清除对应记录，不会产生"幽灵时长"

### 二十九、备份导入导出优化

#### 备份内容精简

原先的直播间序列化会把所有字段一股脑塞进 JSON（包括主播头像 URL、封面图 URL、公会名称、上次直播时间、AI 看点列表等大量运行时动态数据），导致备份文件膨胀、恢复时还可能因为字段不兼容而出错。toJson 逻辑大幅精简，只保留真正需要持久化的核心字段，移除了所有运行时可重新获取或与备份无关的冗余数据。

#### 新增设置项备份

备份控制器的导入导出范围扩展，新增以下项目：

- **面板尺寸**：侧边栏宽度等记忆化的面板尺寸设置
- **窗口几何**：主窗口大小、位置、所属显示器 ID、Windows 物理几何快照（跨缩放显示器精确恢复）
- **房间卡片配置**：卡片样式相关的自定义设置
- **收藏控制器偏好**：置顶开关状态、在线房间排序模式（按热度 / 按开播时间 / 按观看时长）、排序升降序方向
- **观看时长数据**：所有关注直播间的累计观看时长，以键值对形式整体备份和恢复
- **标签管理数据**：自定义标签及其与直播间的绑定关系
- **备份目录路径**：用户自定义的备份文件存储位置

所有新增导入项都有健壮的类型检查和默认值兜底，从不含这些字段的旧版本备份文件恢复时不会报错。观看时长在导入时**整体替换**（以备份文件为准），旧版本备份不含该字段时不触碰现有数据，保证向后兼容。

#### 选择性导入

备份导入页面新增**模块勾选**能力：每个设置模块（应用、主题、播放器、弹幕、窗口、收藏、历史、标签、房间卡片、观看时长等）都是独立的可选项。导入时只应用勾选的模块，未勾选的模块保持当前值不变。这解决了"只想导入标签数据但不想覆盖播放器设置"等混合场景的需求。v2 新格式和 legacy 扁平格式都支持选择性导入。

#### 房间卡片配置字段重命名 + 兼容

房间卡片模型内部多个字段做了语义重命名（如 `cardBorderRadius` → `cornerRadius`、`showSubtitle` → `showAnchorName`、`showPlatform` → `showPlatformBadge`、`showRecordBadge` → `showReplayBadge`），fromJson 同时识别新旧键名，旧版本备份恢复时自动映射到新字段，不会丢失配置。

### 三十、设置项本地持久化

收藏页面的置顶开关（enablePinned）、排序模式（onlineSortMode）、排序升降序方向（onlineSortAscending）现在使用轻量的键值存储持久化到本地，应用重启后自动恢复上次选择，无需重新设置。

### 三十一、窗口位置与显示器记忆化（未完成）

#### 功能概述

桌面端应用的主窗口在关闭时会记录当前的窗口大小、位置以及所在显示器身份，下次启动时自动恢复，避免每次都手动调整到习惯的位置和尺寸。该功能默认关闭，需在设置中手动开启。

#### 恢复策略：物理几何优先，逻辑坐标兜底

Windows 平台采用两级恢复策略：

1. **物理几何恢复（优先）**：通过 Win32 API 捕获当前显示器的 EDID 身份、窗口的物理矩形和显示器原点，下次启动时先确认记忆的显示器是否存在、窗口矩形是否仍在有效显示区域内，再精确落位。这种方式在多显示器、高 DPI 缩放、显示器交换端口等场景下不会偏移。
2. **逻辑坐标恢复（兜底）**：物理几何恢复失败（如目标显示器不存在）时，退回到逻辑坐标（x/y + displayId）恢复。如果记忆的显示器 ID 找不到，完全跳过，保持默认居中间态，避免把窗口放到已断开的显示器上导致"窗口消失"。

macOS / Linux 使用单一逻辑坐标恢复（displayId 匹配），行为一致。

#### 最大化状态：独立记忆，不污染还原基准

最大化标记独立持久化，与窗口大小/位置解耦：

- 窗口关闭前最后固化一次最大化状态，覆盖退出路径漏掉中间事件的场景
- 恢复顺序是**先落位 → 再最大化**，Windows 的"还原"边界就是本次落位的几何，之后取消最大化时自然回到用户记录的大小和位置
- 窗口移动事件中，最大化和全屏状态下的矩形不参与记忆（因为最大化时的窗口矩形不是用户期望的还原尺寸）

#### 边界条件处理

- 显示器不存在时跳过位置恢复，保持默认居中，不会盲恢复到屏幕外
- 最大化标记恢复独立于位置恢复，即使位置恢复失败，最大化也能正常应用
- 位置记忆有 500ms debounce，拖动窗口过程中不会高频写入

## ✨ 核心功能

### 🎬 多平台直播

- 聚合多个主流直播平台。
- 支持平台分区浏览。
- 支持跨平台搜索。
- 支持直播 / 未开播筛选。
- 支持综合、平台顺序、观众和粉丝等排序方式。
- 各个平台保持独立分页状态。
- 快手保留网页搜索入口。
- 离线频道按照平台接口实际返回结果展示。

### ▶️ 多播放器

Android / Android TV 支持多个播放器：

- IJKPlayer
- EXOPlayer
- MPV Player

当某个播放器出现黑屏、卡顿、硬解兼容性问题或者特定直播流无法播放时，可以在设置中切换播放器。

Windows、Linux、macOS 等桌面平台使用对应平台的播放器实现。

### 🖥️ 多画面同看

- 支持双画面、四画面和一大多小聚焦布局。
- 每格独立播放、暂停、音量、清晰度和线路，只有聚焦画面出声。
- 聚焦画面可接入平台弹幕；快速切换使用最新音频焦点，避免多个画面同时出声。
- 移动端最多同时保留 4 路解码，桌面端最多 9 路，并可让小画面自动使用低清晰度以控制占用。

### 💬 弹幕系统

提供完整的弹幕控制能力：

- 弹幕过滤
- 用户屏蔽
- 关键词屏蔽
- 弹幕描边
- 弹幕透明度
- 字号调整
- 速度调整
- 显示区域调整
- 最大弹幕数量
- 发送间隔控制
- 刷新 FPS
- 平台原始颜色
- 统一弹幕颜色
- 应用界面动态最高刷新率，弹幕渲染智能省电适配
- 弹幕点击与长按操作
- 字体粗细与观看模板联动
- 精确重复和相似文本两级过滤

弹幕系统采用房间会话隔离、平台消息 ID 去重以及过期队列淘汰机制，减少切换直播间后出现：

- 串房弹幕
- 重复弹幕
- 旧弹幕重新出现
- 几分钟前积压弹幕突然播放

### 🪟 小窗弹幕

进入：

**设置 → 视频设置 → 小窗弹幕**

或者在直播间进入：

**弹幕设置**

即可配置小窗弹幕。

支持：

- Android 系统画中画
- Windows 小窗
- 应用内悬浮窗
- 独立弹幕控制器
- 独立弹幕队列
- 独立弹幕样式
- 自动根据窗口尺寸缩放
- 最大弹幕数量
- FPS 调整
- 速度调整
- 显示区域调整
- 弹幕字号和透明度
- 弹幕点击和长按

小窗弹幕不会污染主播放器弹幕队列。

配置会保存到本地，下次进入直播间后继续生效。

"最佳观看"模板默认将弹幕限制在画面顶部约 20% 区域，以减少弹幕对画面的遮挡。

主播放器、小窗以及 Windows 桌面端统一使用 px/s 速度和逻辑帧时钟。

切换横竖屏或者应用从后台恢复时，不会根据后台停留时间产生大量弹幕补跳。

### 📺 高刷新率

Android 支持根据设备显示模式动态适配刷新率：

- 自动监听当前显示模式
- 请求当前分辨率支持的最高刷新率
- 适配 60 Hz / 90 Hz / 120 Hz 等高刷新率设备
- 优化封面图片解码
- 优化图片缓存
- 优化弹幕重绘
- 应用界面跟随设备最高刷新率；自动弹幕主画面 60 FPS、小窗 30 FPS，手动模式最高 240 FPS

## 🎧 ASMR / 助眠模式

Android 支持 ASMR 助眠模式。

可以设置：

- 新房间自动进入纯音频
- 媒体保活
- 自定义自动停止时间
- 后台持续播放

房间内的耳机图标只控制当前房间的纯音频状态。

电视图标用于投屏。

前台手动进入音频模式时保留同一播放器的视频解码热状态，切回画面通常可直接复用当前纹理；应用进入后台后立即停用视频轨以降低解码和电量开销，回到前台再静默预热。深度恢复期间显示低开销音频卡片和明确进度，不再以黑屏或整页转圈阻塞操作。

当前各平台通常返回音视频复用直播流；关闭视频轨主要节省解码、GPU 与电量，并不等同于只下载音频。只有平台明确提供独立音频地址时，才可能同时实现网络流量显著下降和无等待画面恢复。

- 直播录制

进行长时间观看或助眠使用。
